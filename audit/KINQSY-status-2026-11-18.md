# KINQSY — статус аудита и исправлений

Дата: 18 ноября 2026. Это промежуточная сводка, не подтверждение полной безопасности проекта.

## Исправления frontend

PR 1, 3 и 4 объединены с main. Подтверждена публикация нового media helper на шести страницах и исправления Notes на kinqsy.lol.

- Пересылка Gossip использует chat_sessions и выбор друга с обеих сторон связи.
- URL изображения Notes экранируется перед вставкой в HTML.
- Убраны исследованные резервные сохранения Notes/Dreams без оформления.
- Dreams v3 повторно открывается в редакторе раскладки.
- Чат освобождает каналы и таймеры; сохраняется позиция чтения.
- Изображения media показываются через временные ссылки; постоянные данные не должны сохранять токены.
- Измерение пропорций загруженного изображения тоже использует временную ссылку.
- Исправлено переполнение длинного текста старого редактора Notes.

## Изменения Supabase, подтверждённые результатами пользователя

- У gossip_layouts отозваны клиентские INSERT/UPDATE/DELETE; authenticated SELECT сохранён.
- Триггер chat_block_client_end запрещает подмену ID и участников и изменение чужой отметки прочтения.
- can_view использует позиционные аргументы: настройки Notes/Dreams не смешиваются из-за s.section = section.
- Включены два триггера дружбы: только pending INSERT, принятие адресатом, неизменность участников, лимит пять, уникальность ненаправленной пары.
- media стал private. Старый публичный URL тестового файла проверен HEAD-запросом: HTTP 400 вместо изображения.
- Закрыт прямой EXECUTE admin_audit_write для anon/authenticated. Полный применённый скрипт также ограничивает report_context категорией Gossip и вставку жалоб видимыми Gossip-постами.
- gossip_media_visible сопоставляет владельца объекта с автором поста; полный применённый скрипт ограничивает владельца загрузки.

Факт применения не равен полной проверке всех пользовательских сценариев. Для некоторых изменений подтверждено только определение функции/ACL, присланное пользователем.

## Выполненные проверки

- Синтаксический разбор 28 внешних и inline JS скриптов на этапе первого PR.
- Пять изолированных сценариев пересылки Gossip и проверки очистки ресурсов чата.
- Тестовый PostgreSQL 16: конкурентное принятие дружбы не превышает пять; обход согласия и обратный дубль отклоняются.
- Тестовый PostgreSQL 16: Storage RLS для владельца, разрешённого читателя и постороннего; подставленная чужая ссылка не открывает файл.
- Реальный Chrome с локальной имитацией Storage: девять проверок signed image, обновления ссылки, editor round-trip и смены сессии.
- Пользователь подтвердил изображения Notes/Dreams и их редакторов после закрытия media; скриншотом подтверждено устранение наложения текста.
- Production read-only: гостевые API-запросы не вернули личные посты/профиль.
- Read-only SQL с синтетическим auth-контекстом: постороннему запрещены пять личных разделов; личные posts/profiles/media вернули ноль строк.
- Тестовый PostgreSQL 16: семь проверок границы жалоб/аудита и девять проверок отдельного gossip-media.
- Тестовый PostgreSQL 16: реакция on/off, замена, запрет гостю/постороннему, две конкурентные одинаковые и две разные реакции.

Имитации не заменяют production PostgreSQL 17.6, реальный Storage HTTP, JWT и отдельный настоящий аккаунт.

## Подготовлено, но ещё не подтверждено в production

- fix-gossip-reaction-toggle.sql: сериализация RPC по пользователю и посту, безопасная проверка доступа, корректный UPSERT вместо ложного успеха ON CONFLICT DO NOTHING.
- Проверка накрывает конкурентные вызовы этого RPC. Прямые разрешённые записи reactions через REST не участвуют в advisory-блокировке; от дублей защищают уникальные индексы.

## Оставшиеся вопросы

1. Realtime: в первоначальном снимке публикации отсутствовали public.messages и public.chat_sessions. После этого состояние не перепроверялось.
2. Нет полного теста с двумя реальными аккаунтами, в том числе отзывом дружбы и selected-доступа.
3. Не выполнен полный мобильный, клавиатурный и экранный аудит всех страниц.
4. Пагинация чата и лент, N+1-запросы, гонки запросов при смене аккаунта остаются техническим долгом.
5. admins и staff_members — две модели полномочий. Сейчас по результату пользователя один legacy admin, активных сотрудников нет, лишних nonowner admin не найдено.
6. Нужны явные проверки NULL в owner-only RPC; полный аудит всех RPC, антиспама и удаления аккаунта не завершён.
7. Уже выданные signed URL остаются доступны до истечения. Они не отзываются немедленно при изменении прав.
8. Сохранён один старый тестовый файл без владельца. Он не удалён и не переназначен; публичный доступ закрыт.
9. Для 11 файлов связь с posts не была найдена предварительным поиском. Это не основание считать их неиспользуемыми или удалять.
10. Не решено, должен ли Gossip читаться гостями. Текущие функции требуют авторизацию; поведение сохранено.
11. SQL, выполнявшийся вручную, необходимо свести в воспроизводимую историю миграций. Слияние SQL-файла на GitHub само по себе не применяет его в Supabase.
