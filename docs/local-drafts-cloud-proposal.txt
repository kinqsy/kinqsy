KINQSY — предложение будущего облачного хранения черновиков
Не миграция. Никакие команды Supabase на этом этапе не выполнялись.

Отдельная таблица public.diary_drafts:
  id uuid — primary key;
  owner_id uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE;
  section text NOT NULL CHECK (section IN ('notes','dreams'));
  title text NOT NULL DEFAULT '';
  content text NOT NULL DEFAULT '';
  payload jsonb NOT NULL — полный payload, включая decor v3 и оформление;
  revision bigint NOT NULL DEFAULT 1 CHECK (revision > 0);
  created_at timestamptz NOT NULL DEFAULT now();
  updated_at timestamptz NOT NULL DEFAULT now().
Индекс (owner_id, section, updated_at DESC). Размер JSON и длины текстов ограничиваются после сверки с фактическими лимитами проекта.

Таблица не входит в представления Gossip, ленту posts или публичные RPC. Черновик не является публикацией независимо от будущей visibility публикации.

RLS обязательно включена. SELECT/INSERT/UPDATE/DELETE только для authenticated и только при owner_id = (SELECT auth.uid()). INSERT/UPDATE требуют WITH CHECK с тем же условием. Пользователь не может менять owner_id. У anon и PUBLIC нет прав на таблицу и управляющие RPC. Политики чтения друзей и массового административного чтения черновиков по умолчанию не нужны.

Серверный протокол записи:
1. uid берётся из auth.uid(), а не из доверенного поля клиента.
2. UPDATE атомарно проверяет id + owner_id + expected_revision.
3. При несовпадении revision возвращается конфликт без перезаписи. Клиент выбирает версию либо создаёт отдельный документ.
4. revision и updated_at меняет сервер. Не давать обходить этот протокол прямым UPDATE. Отдельно проработать минимальные grants/RPC, закрепить search_path и проверить anon/authenticated.
5. Удаление проверяет revision, чтобы старая вкладка не удалила свежую версию.

Ручные документы и аварийные копии — разные сущности. Облачную синхронизацию аварийных версий проектировать отдельно, с политикой срока хранения и количества копий; локальная реализация сейчас не удаляет их по сроку автоматически.

Изображения: ссылки на приватные объекты Storage без временных signed URL. Права чтения файлов проверяются отдельно. До облачного запуска необходимо разрешить чтение ещё не опубликованных файлов и учитывать ссылки при очистке неиспользуемых файлов. Удаление черновика не должно удалять файл, используемый другой записью.

Перенос локальных документов в облако — явное действие с проверкой владельца, раздела, версии и подтверждения сервера. Пока облачного сервиса нет, синхронизация между устройствами не обещается.

До внедрения: сверить схему Supabase; подготовить отдельную миграцию; проверить RLS двумя аккаунтами, гостем и конкурентными запросами; согласовать применение. Эта записка ничего не создаёт в production.
